Documentação da API

Introdução

Esta aplicação foi criada para fins de estudo no ramo de desenvolvimento web e inteligência aritficial. A API foi desenvolvida em Django a fim de ser compatível com um algoritmo de IA simples para analisar os dados de sono e prever se o usuário terá ou não um dia produtivo dependendo de seus horários. Como referência, usamos este dataset para formular as entradas de usuário.

Para um guia de instalação e de como começar a contribuir, acesse o arquivo README do nosso repositório.

Variedades

Anatomia de um fetch

Para obter e enviar dados para a API, você deve fazer um fetch para a rota desejada, com método esperado e os demais requisitos detalhados na documentação. Seguem exemplos de fetch em JavaScript: 


                    // Fetch de método GET (obter informações)
                    fetch('https://api-sonhario.onrender.com/entries/', {
                    method: 'GET',  // <-- Método definido aqui
                    headers: {
                        'Content-Type': 'application/json',
                    }
                    })
                    .then(response => response.json())
                    .then(data => {
                    // Código executado após sucesso
                    })
                    .catch(error => {
                    // Código executado após erro
                    });
                    

                    // Fetch de método POST (enviar informações)
                    fetch('https://api-sonhario.onrender.com/token/', {
                    method: 'POST',  // <-- Método definido aqui
                    headers: {
                        'Content-Type': 'application/json',
                    },
                    body: JSON.stringify({  // <-- POST requests precisam de um body
                        username: 'john_doe',
                        password: 'password',
                    }),
                    })
                    .then(response => response.json())
                    .then(data => {
                    // Código executado após sucesso
                    })
                    .catch(error => {
                    // Código executado após erro
                    });

Note que os exemplos de body para as rotas de método POST estão em JSON, mas deverão ser escritas como um objeto JavaScript no código. 


                    // Exemplo de body em JSON
                    {
                    "username": "john_doe",
                    "email": "example@mail.com",
                    "password": "password"
                    }
                    

                    // Mesmo exemplo em JavaScript
                    body: JSON.stringify({
                        username: 'john_doe',
                        email: "example@mail.com",
                        password: 'password',                        
                    })

O URL usado nestes exemplos é o endereço em produção da API. Você talvez queira utilizar uma variável de ambiente para que a aplicação funcione tanto com um URL local quanto o de produção.

Enviando token de autenticação em um fetch

A API usa um sistema de autenticação por token (JWT) para o acesso da grande maioria das rotas relacionadas ao usuário. Após o login de um usuário, o seu token deve ser salvo em cache na aplicação e enviado a todas as demais rotas da seguinte forma: 


                    const jwtToken = 'TOKEN_JWT_AQUI';

                    fetch('https://api-sonhario.onrender.com/entries/', {
                    method: 'GET',
                    headers: {
                        'Content-Type': 'application/json',
                        'Authorization': `Bearer ${jwtToken}`,  // <-- Token incluso aqui
                    }
                    })

O sistema retornará um erro em rotas de usuário caso o token esteja ausente ou inválido. 


                    // Resposta de erro (401)
                    {
                    "detail": "As credenciais de autenticação não foram fornecidas."
                    }

Erros de dados faltantes

É importante entender como se porta uma resposta de erro de campos obrigatórios faltantes. Estará contida no objeto a label de cada atributo faltante ou inválido e a mensagem de erro correspondente. Isto pode ser usado para exibir erros específicos em cada input. A única rota que não segue este padrão é /register_check/. 


                    // Resposta de erro (400)
                    {
                    "display_name": [
                        "Este campo é obrigatório."
                    ],
                    "birthdate": [
                        "Este campo é obrigatório."
                    }

Paginação em rotas de listagem

Todas as rotas de listagem da API suportam paginação usando parâmetros de query. Você pode definir o limite de cada página com "limit" e o número da página atual (começando em 0) com "step". Observe o exemplo abaixo: 


                    // Fetch com limite de 7 objetos
                    fetch('https://api-sonhario.onrender.com/entries/?limit=7', {
                    method: 'GET',
                    headers: {
                        'Content-Type': 'application/json',
                        'Authorization': `Bearer ${jwtToken}`,
                    }
                    })
                    

                    // Fetch na segunda página com um limite de 10 objetos
                    fetch('https://api-sonhario.onrender.com/entries/?limit=10&step=1', {
                    method: 'GET',
                    headers: {
                        'Content-Type': 'application/json',
                        'Authorization': `Bearer ${jwtToken}`,
                    }
                    })

Autenticação

POST

/register_check/

Checa se um usuário já existe a partir de seu nome de usuário e email. Retorna uma mensagem de erro caso o usuário já exista. 


                    // Body
                    {
                    "username": "john_doe",
                    "email": "example@mail.com",
                    "password": "password"
                    }
                    

                    // Resposta de sucesso (200)
                    {
                    "message": "Seu nome de usuário e email estão dispníveis"
                    }
                    

                    // Resposta de erro (400)
                    {
                    "error": "Este nome de usuário já está em uso"
                    }
POST

/register/

Além de repetir a checagem da rota anterior, completa o cadastro de um usuário no sistema. 


                    // Body
                    {
                    "username": "john_doe",
                    "email": "example@mail.com",
                    "password": "password",
                    "display_name": "John Doe",
                    "birthdate": "2000-04-01",
                    "gender": "Male"
                    }
                    

                    // Resposta de sucesso (200)
                    {
                    "message": "Usuário registrado com sucesso!"
                    }
POST

/token/

Envia o username e senha de um usuário para obter os tokens de acesso. 


                    // Body
                    {
                    "username": "john_doe",
                    "password": "password"
                    }
                    

                    // Resposta de sucesso (200)
                    {
                    "refresh": "EXEMPLO_DE_TOKEN",
                    "access": "EXEMPLO_DE_TOKEN"
                    }

O token "access" dura pouco tempo (de 10 a 15 minutos). Este é o token que deve ser enviado para rotas que exigem autenticação.

O token "refresh" pode durar muito mais tempo (dias, semanas) e serve para atualizar o token de acesso do usuário. Este token deve ser salvo em cache e enviado apenas à rota /token/refresh/ para obter um novo token de acesso.

POST

/token/refresh/

Envia um token do tipo "refresh" para receber um novo token de acesso. 


                    // Body
                    {
                    "refresh": "EXEMPLO_DE_TOKEN"
                    }
                    

                    // Resposta de sucesso (200)
                    {
                    "access": "EXEMPLO_DE_TOKEN",
                    "refresh": "EXEMPLO_DE_TOKEN"
                    }
                    

                    // Exemplo de fluxo de refresh
                    const refreshToken = async () => {
                    try {
                        const storedRefreshToken = await getRefreshToken();  // <-- Apenas um exemplo. O token deve ser obtido do cache de alguma forma

                        const response = await fetch('https://api-sonhario.onrender.com/token/refresh/', {
                        method: 'POST',
                        headers: {
                            'Content-Type': 'application/json'
                        },
                        body: JSON.stringify({
                            refresh: storedRefreshToken
                        })
                        });

                        if (response.ok) {
                            const data = await response.json();
                            const newAccessToken = data.access;
                            saveAccessToken(newAccessToken); <-- Apenas um exemplo. O token deve ser salvo cache de alguma forma
                        } else {
                            // Neste caso o refresh token expirou. O usuário será deslogado.
                        }
                    } catch (err) {
                        // Erro no fetch
                    }
                    };
